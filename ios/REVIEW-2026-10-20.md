# iPad app review — 2026-10-20

Code + security review of the new iPad app (`ios/`) and the server/web changes made with it,
done the day it was written, before any commit. Reviewer: a separate reviewer session with a
read-only brief ("think like a student trying to cheat on an iPad"). Verdict: **fix C1, H1,
M1–M3 before shipping; then re-review.** Crypto, navigation policy and dev-code gating are sound.

Status column updated 2026-10-20 after the fix pass (see "Fix pass" at the end).

## Critical

| # | Where | Finding | Status |
|---|---|---|---|
| C1 | `ios/FairPlay/ExamViewController.swift` `showBlocking` | The red blocking screen is inserted `belowSubview: bar`; subview order is `[bar, webView]`, so it lands at index 0 **under the opaque web view**. Every "problem blocks the exam" case (recording/mirroring, extra display, Split View, jailbreak, debugger, Assessment Mode interrupted) is invisible; the student keeps working. Only the beats (`locked=0`) and events still fire. **Scenario:** Assessment Mode is interrupted (or the student ends Guided Access, see H1), they go to Safari, come back, keep answering. **Fix:** `insertSubview(v, aboveSubview: webView)` then `bringSubviewToFront(bar)`; add a hit-test check. | **fixed** — inserted above the web view, bar kept on top; verified in the simulator (red screen covers the exam and swallows taps) |

## Medium

| # | Where | Finding | Status |
|---|---|---|---|
| M1 | `AppSession.swift` `isLockedNow` → `lockedProvider` = `reallyLocked` | Attempt-swap guard and `LockMarker` key off `reallyLocked`, which drops to false while Assessment Mode is interrupted. In that window `setExam` accepts a `session`/`lock` for another attempt or student (breaks the CONTRACT "while locked, refuse another attempt" rule; a submitted attempt then unlocks via hand-in), and a token refresh deletes the LockMarker while still locked (exactly when a kill is likely). **Fix:** use `LockdownController.shared.isLocked` for both; keep `reallyLocked` only for the beat's `locked` bit. | **fixed** — `lockedProvider` = `isLocked` (session guard, LockMarker); new `heldProvider` = `reallyLocked` for the beat bit only; marker only written while locked |
| M2 | `AppSession.swift` `fetchOfflineKey`; `server/app/routes_student.py` offline-key route | Offline key accepted **without** proof when the `proof` field is absent (`if let proof`). A late `didBegin` from session A can consume B's completion; if B fails, `session = nil` while A is active but unreferenced → `isActive` false → blocked forever mid-exam, and `end()` can't reach A → **iPad stays in Assessment Mode after unlock until restart**. `onLateBegin`'s `else { assessment.end() }` ends the current session, not the stale one. ## Info

- `Readiness.tsx` always shows "Assessment Mode ready" on iPad without checking anything (copy only).
- `nativePlatform()` sniffs the user agent; `state.platform` (already sent) would be more reliable. Only copy depends on it.
- **`lockPending` cannot be abused:** fake events need the bridge nonce, other sites can't dispatch into the server page, and native always finishes (120 s begin timeout → SAM callback → `finishLock` stops the timer). A stuck "locking" screen gives a cheater nothing.
- **App Attest is a stub:** `att` is always `?` on hardware. CONTRACT M-20 still says App Attest closes the extracted-key gap; nothing implements it yet.
- Restarting the iPad always exits (inherent; Assessment Mode can't stop power-off). Server sees `app_gap`; `previous_run_killed` only if FairPlay is reopened.
- `UIRequiresFullScreen` is deprecated in iPadOS 26; the `isMultitasking` check is the real guard, and it depends on C1.

## Checked and found OK

- **Protocol parity with `server/app/app_client.py`:** start / beat / offkey / handin / exit / offkey-resp message strings match byte for byte; HMAC lowercase hex; constant-time compares; hand-in and exit check all `proofs` against the nonce; `unlockAllowed` = submitted/gone/moved only.
- **Field validation:** device id `ipad-`+32 hex (37 chars) fits `^[A-Za-z0-9-]+$` 8..64; `checks` ≈120 chars, cut to 200 before signing; `ts` strictly increasing shared counter; per-request UUID-hex nonce; aid/session through `isSafeToken` (no `|`); LockMarker ids re-validated on read.
- **Unlock paths:** page alone cannot unlock; needs the signed hand-in. `unlockRetry` created once, invalidated in `endLock`. Token-only update keeps the offline key; session change refetches it.
- **Offline exit:** vectors match server tests (`06710479`, `37496243`); 5 wrong → 5 min; new challenge per lock; no key in release → no offline exit.
- **Bridge origin:** main frame + scheme + host + port (default port handled). Nonce script only on the server origin, main frame; nonce and origin filtered.
- **Navigation:** teacher paths blocked in all frames and by the URL-watch bounce; `allowedWhileLocked` on main-frame server URLs; the `about:blank` iframe exception is exact-match, sub-frame only, no bridge access; `createWebViewWith` re-runs the policy via `load`; `tel:` / `mailto:` / `data:` / blob blocked; `SiteRule` matches exact hosts and whole path segments.
- **Dev-only code** all behind `#if FAIRPLAY_DEV`: soft lock, simulator skip of Assessment Mode, `DevExitCode`, offline fallback key, server override, DebugLog, http, `isInspectable`, CaptureShield-off switch.
- **Release build settings:** no `FAIRPLAY_DEV`; Archive uses Release; no ATS exceptions (dev keeps `NSAllowsArbitraryLoads` in Info-Dev only); `TARGETED_DEVICE_FAMILY=2`; Catalyst / designed-for-Mac / visionOS off; entitlements carry Assessment Mode + App Attest (production for release); `FairPlayBuild.plist` gitignored; `configure-release.sh` requires https, a non-dev 32+ char key and well-formed pins.
- **TLS:** default trust first, then pins on the server host; native session ignores the system proxy.
- **Web view / input:** edit menu is an allow-list (no Copy / Paste / Look Up / Translate / Share / Writing Tools, incl. hardware Cmd-C/V); pasteboard cleared on lock and on change; third-party keyboards refused; Writing Tools off; AirPlay, PiP, data detectors, link previews, back-swipe off; external displays get a black scene; the privacy cover **is** added on top (unlike C1).
- **Lifecycle:** `WeakScriptHandler` breaks the retain cycle; KVO/timers use weak captures; `MainActor.assumeIsolated` only in main-run-loop timers and main-queue observers; waiters on an in-progress lock are all completed.
- **Logs:** no tokens, codes or answers in EventLog/DebugLog; log folder excluded from backup; file protected until first unlock.
- **Server diff:** new client event types cover everything the iPad records; `off_console` iPad wording tested with checks echoed in live. Not covered: `offkey-resp` vector, `soft=1` handling.
- **Web diff:** `requestLock` timer restarts on `lockPending`; both new tests sound; UI changes copy-only.

  most likely the page still loading. The shield is now checked properly with the dev
  self-test against iPadOS's snapshot path (HIDDEN with shield, VISIBLE without, iPadOS 26.5).
  `simctl io screenshot` reads the simulator display directly and can't show the shield.

- New dev-only hooks for testing: `-DevForceCapture YES`, `-ShieldSelfTest YES` (compiled out
  of release builds).
