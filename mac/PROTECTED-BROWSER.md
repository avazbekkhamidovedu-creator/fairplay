# Protected browser: basic client-only prototype

Open **View → Protected Browser…** in the Mac app. This separate entry leaves the existing student login, exam codes, start-exam flow and server unchanged.

1. Enter the university address; a bare address uses HTTPS. Exact DNS names, intranet names, localhost, IPv4/IPv6 and custom ports are supported. Add each required login/resource origin explicitly; scheme, host and effective port must match, and wildcard domains are rejected. HTTPS certificate validation remains unchanged.
2. Check this Mac. Save work before choosing **Lock and open**; the existing native lock may close other apps.
3. Website restrictions compile first, native pre-lock must succeed, then a separate ephemeral WKWebView opens the university page.
4. **Leave and unlock** destroys the WebView first, then releases this mode's pre-lock. It never submits answers. The existing emergency pre-lock exit remains available.

Configuration is in-memory client data, not university registration. No tokens, exam attempts, question imports, submission calls or institution adapters are added. The WebView has no FairPlay JavaScript message handler, no shared persistent website store, and no cross-mode navigation authority. While its native overlay is open, the retained FairPlay page cannot drive bridge actions or navigation.

Website JavaScript alerts, confirmation dialogs and text prompts use origin-labelled native sheets. Confirmations require an explicit OK; cancellation, navigation, a security blocker or lock loss never approves submission. Every sheet offers Leave and unlock. Pending callbacks complete once and are cancelled when the browser is discarded.

The university remains responsible for login, exam content and submission. Only the configured origins load; additional CDN/SSO origins may be necessary. User-initiated sign-in popups use WebKit’s supplied configuration to retain their opener and the same temporary website store and resource restrictions. At most four nested child windows are allowed; only the active window can present website dialogs. Close sign-in window returns to the parent without unlocking. Automatic JavaScript popups remain disabled. File upload/download, camera/microphone and some LMS features remain unsupported. Real university SSO compatibility has not been verified. Leaving is always possible and is not proof of exam completion. This does not prevent another browser/device from reaching the university, protect already-downloaded files, or attest enrollment/lock state to the university.

The native toolbar displays the current committed origin without its path or query, plus loading/failure status. Reload is available after a load failure and explicitly retries the last permitted main-frame URL, even if no document ever committed; the destination is checked against the current exact-origin policy again. Error-provided URLs are never used as retry destinations. A security interruption or renderer crash discards every parent and child page while retaining the lock; Leave and unlock remains available, and unusable navigation controls are disabled.

Tests cover policy parsing, lookalike/credential/port denial, cancellation and stale callbacks, lock-before-content ordering, clear-before-unlock ordering, and actual WebKit content-rule compilation. An isolated AppKit coordinator test uses inline HTML and fake lock effects to verify popup opener preservation, shared ephemeral store and resource controller, external popup rejection, return to the still-locked parent, stale-child callbacks and all-page teardown after a child renderer crash. That fixture enables automatic JavaScript popups only in its injected test configuration because script evaluation has no physical user gesture; it does not prove a real user click or live SSO. A separate real-WebKit regression demonstrates that reload has no request on an uncommitted empty view, then verifies explicit first-load retry, rejection of an untrusted URL supplied by the injected error and disabled retry after page disposal. Tests never activate the actual native lock. A physical Mac walkthrough with Accessibility enabled and a permitted test university account is still required before production use.

Development builds offer an unchecked HTTP option for IP addresses, unqualified intranet names and `.local` names. HTTP is unencrypted: others may read or alter the page and its traffic. Never enter passwords or sensitive information on HTTP. IP addresses may be public; accepting an IP address does not establish that it is on a private network. Only loopback HTTP has been verified in the real WebKit fixture. Public DNS-named HTTP sites are unsupported, and the HTTP option is disabled in non-development builds. ATS settings are unchanged: this uses the existing development local-network allowance. HTTPS is never silently downgraded, and certificate failures are never bypassed.

Blocked navigation shows the target origin rather than its path or query. Load failures show a sanitized Foundation/WebKit error domain and numeric code; failing URLs are used only for safe origin display, never as retry destinations. Leaving and explicitly adding a trusted missing SSO origin is required; redirects do not expand the allowlist automatically.
