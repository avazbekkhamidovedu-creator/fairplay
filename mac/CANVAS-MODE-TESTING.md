Canvas mode: manual tests on the Mac app

Canvas mode needs no access code. The teacher builds the quiz in Canvas without a code. FairPlay keeps the student on the exam course and quiz, and once the quiz has started the student cannot leave before submitting. Use a test Canvas course with a quiz without an access code, a second course, another quiz in the same course, and a course with pages, modules and files. The server must send canvas_scope.


1. Blocked host: in the quiz, open a link to a host that is not allowed (also try window.open to one). Nothing opens and blocked_navigation is recorded.
2. Duo / Microsoft sign-in popup: sign in through the SSO popup. On macOS 14.4 and newer the popup may stay a child window; on older macOS it opens in the main view. Both end signed in. canvas_sso_popup is recorded. A second popup while one is open is blocked.
3. File upload question: open a quiz with a file upload question and click the upload button. No file panel opens and canvas_upload_unsupported is recorded.
4. Ordinary website exam: run a normal (non-Canvas) website exam. Allowed sites, finish URL, the Finish exam button and unlock behave as before.
5. Sign in and dashboard: start a Canvas exam while signed out of Canvas. Sign in. When Canvas lands on the dashboard (or the course page), the app opens the exam quiz page once by itself. Go back to the dashboard by hand: it is not opened again.
6. Another course: before the quiz starts, open the dashboard, click another course. The page does not open, the strip shows "This page is not available during the exam." for a few seconds and blocked_navigation (canvas page /courses/<id>) is recorded. The quiz's own course page, the course quiz list and the exam quiz page do open.
7. Inbox and other pages: click Inbox, Profile, Calendar, Groups, Account in Canvas global navigation. All blocked with the message and an event, before the quiz and during it.
8. Quiz opens: open the exam quiz. It starts without any code being asked or typed by the app. Another quiz of the same course is blocked.
9. Quiz phase: once the quiz page (classic: Take the quiz; new quizzes and assignments: the assignment page) has loaded, the dashboard, the course page and the course quiz list are blocked too. The quiz, its results page, sign-in hosts and Canvas /login pages keep working: let the Canvas session expire (or sign out in another browser) mid-quiz and check that signing in again works.
10. Open book off: during the quiz, Pages, Modules and Files links of the course are blocked.
11. Open book on: the teacher turns on open book and a new attempt starts. Course pages, modules and files open during the quiz; a file download link (/files/<id>/download) stays blocked; Inbox and other courses stay blocked.
12. Go to my quiz: from any allowed page, press "Go to my quiz" in the strip. The exam quiz page opens. Press it while on the quiz or while a page is still loading: nothing happens.
13. Back: with a previous allowed page in the history, "Back" goes there. During the quiz Back only returns to pages of the exam's Canvas host that are not sign-in pages. On the first page (history holds only the FairPlay page) or when the previous page is not allowed, Back is greyed out. Back never reaches a blocked page.
14. Popups and typed addresses: window.open or a link with target=_blank to /inbox is blocked with the message. Path tricks in a link (/courses/<id>/quizzes/<id>/../../../inbox, %2f, //) are blocked.
15. In-page route changes: in the new quizzes or assignment page, use any in-page link that changes the address without a page load (for example a Canvas global navigation item in an open-book exam, or a link to /inbox). If the address becomes a blocked page, the app returns to the previous allowed page (or the exam quiz) within about a second, shows the message, and records one blocked_navigation (canvas page /... (in page)) per page. Clicking the same link repeatedly never makes the page flicker more than once per second.
16. First login at DKU Canvas: with a student account that has never signed in (or after resetting the terms-of-use acceptance), start a Canvas exam and complete the first-login steps, for example accepting the terms of use. /users, /profile and /accounts are blocked, so check that the first login still finishes and the exam link opens afterwards. If a step needs one of those pages, it must be done before the exam.
17. Broad allowed sites: a teacher-added wildcard such as *.instructure.com lets students follow links to any site under it (also other Canvas hosts and their /profile or /users pages). Check the allowed sites list of a real exam and keep it as narrow as possible.
18. Downloads: with open book on, a link with ?download=1 or ?download_frd=1 on a file is blocked, and a page that answers with an attachment is cancelled with the message.
19. Redirect loop: a link that keeps redirecting to a blocked page adds one blocked_navigation event per page, not one per redirect.
20. Popups: a link that opens a new window to a Canvas page of the exam host loads in the main view, not in a child window. A sign-in popup to another allowed host still works.
21. New Quizzes: the quiz runs in a separate quiz-lti frame. Check that it opens and can be answered and submitted inside the app.
22. Sign-in pages during the quiz: Canvas-host /login and /login/** (same host only, exact path segments) stay open in the quiz phase so an expired session can sign in again. This is an addition to the written contract. Check that /login works during the quiz and that /loginx, /Login and /login/../inbox are blocked.
23. Finish pattern: a Canvas exam only finishes from finish_url_regex; finish_url_contains is ignored. With a finish pattern the app cannot use (too long or unsafe), the strip shows "The finish pattern of this exam is not valid. Your teacher must fix it." and the exam view lists one blocked_navigation event (finish pattern rejected).
24. Web data: after finishing, sign-in cookies of other sites are cleared, but a site that shares its registrable domain with the FairPlay server (for example dku.edu) is kept, so Canvas can stay signed in on a Mac when both are under the same domain. Check which behaviour your deployment has and sign out of Canvas by hand if it matters.
25. Downloads: a link in Canvas that starts a download in the main view (a file attachment link) is cancelled with the message and a blocked_navigation event.
26. Stuck recovery: a page that keeps pushing a blocked address in the quiz brings the view back to the exam quiz up to 5 times at one per second, then once more to the exam link, then stops; the message stays.
27. Lock-in, lobby: before the quiz page has loaded, the strip shows Finish exam and it works (the exam ends after the confirmation).
28. Lock-in, quiz: after the quiz page has loaded the exam view lists canvas_quiz_started once, and the strip has no Finish exam button. Look for any other way to end the exam from the app (menu bar, Cmd-Q, Cmd-W, Cmd-R, window buttons, keyboard shortcuts): none ends the exam. Quit is refused while locked.
29. Lock-in, relaunch: in the quiz, quit the lock with the invigilator emergency exit only for a test, or kill the app and let the watchdog relaunch it, then resume the attempt. The app opens the exam quiz and stays in the quiz phase: the dashboard and the course page are blocked at once, Finish exam is hidden and canvas_quiz_started is not reported a second time.
30. Lock-in, reload: press Reload (Cmd-R) in the quiz and let the page reload: still in the quiz phase, still no Finish exam button.
31. Lock-in, Back and Go to my quiz: in the quiz Back only returns to pages of the quiz itself (never the dashboard, a sign-in page or an open-book page). Go to my quiz opens the quiz link.
32. Lock-in, submission: submit the quiz. About 2 s after the confirmation page the exam ends, the computer unlocks, the quiz marker is gone (open the same exam again as a new attempt: it starts in the lobby phase) and Canvas data is cleared.
33. Lock-in, other ends: the deadline, the teacher closing the exam and the emergency exit still end the exam.
34. New Quizzes finish: in a New Quizzes exam, submit the quiz. The submission screen appears inside the quiz frame and the main address does not change. About 2 s later the exam finishes anyway (finish pattern matched on the frame address). Navigating the quiz frame to a page that does not match never finishes the exam. The frame address is checked only for navigations and responses the app sees, never read back from the frame.
35. Bad finish pattern: with an exam whose finish pattern is missing or rejected as unsafe, the strip shows "The finish pattern of this exam is not valid. Your teacher must fix it." and keeps it after other messages, one blocked_navigation (finish pattern rejected) is recorded, and Finish exam stays visible during the quiz so the student can end the exam.
36. Off-host pages in the quiz: after the quiz has started, a link from the quiz to another website that the exam allows (for example a teacher-added docs.google.com) does not open and the strip shows the message; the view returns to the quiz. Sign-in pages (single sign-on, Duo, Microsoft) and quiz-lti pages still open, also after an expired session sends the student through sign-in and back to the dashboard (the dashboard is blocked, the student stays on the sign-in page and uses Go to my quiz). Before the quiz starts these allowed sites still open. Which hosts count as sign-in and quiz-lti hosts comes from the server list in canvas_scope (sign_in_hosts, quiz_lti_hosts; exact host or *.suffix, https only). A sign-in host with an unusual name that is in the list opens; a teacher-added site that is not in the list is blocked in the quiz. Before the quiz starts, sign-in redirect chains follow the exam's allowed sites as before.
37. Canvas exam without scope: starting a Canvas exam whose canvas_scope is missing is refused (the exam page shows the start error) and the computer stays as it was.
38. Armed finish: after the quiz page (classic: Take the quiz) has loaded, open the quiz landing page with Go to my quiz or Back, then open the quiz's History or a past submission link from it. The exam does not finish. Start the quiz again (Take the quiz) and submit: the exam finishes about 2 s after the confirmation page. Relaunch the app mid-quiz after Take the quiz and submit: it still finishes.
39. Print: in the exam view call window.print() from a Canvas page (or press Cmd-P): nothing prints.
40. Popups in the quiz: during the quiz a window.open or target=_blank link to a teacher-added site that is not a listed sign-in host is blocked (also on macOS 13 to 14.3, where popups can stay child windows); a sign-in popup to a listed host still opens.
41. Relaunch after Take the quiz: the app comes back to the quiz landing page without losing the armed state; submitting the quiz still finishes the exam. Going to the landing page a second time disarms it.
42. Hand-in: after the exam finishes, the quiz marker stays until the hand-in page has loaded; if the Mac loses the network just then, resuming the attempt returns to the quiz phase.
43. Finish address: the finish pattern is matched against the page path only, never the query or the part after #. A Canvas link like /courses/1/quizzes/2?x=/quizzes/1/history does not finish the exam; the real submission or confirmation page does.
