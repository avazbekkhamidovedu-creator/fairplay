Canvas mode: manual tests on the Mac app

Use a test Canvas course with a classic quiz that has an access code, and a teacher account linked to Canvas.

0. Code scope: the code is typed only on /courses/<id>/quizzes|assignments/<id> pages of the exam host. Sign-in and other pages of that host, and SSO hosts, never get it.
1. Managed classic exam: start the exam as a student. The app types the access code into the quiz page and the quiz starts. No code is visible on screen or in the exam page.
2. Wrong manual code: set the exam to manual with a wrong code. The app fills it 3 times, then shows "Ask your teacher for help". The exam view lists canvas_code_failed. The code is never shown.
3. Blocked host: in the quiz, open a link to a host that is not allowed (also try window.open to one). Nothing opens and blocked_navigation is recorded.
4. Duo / Microsoft sign-in popup: sign in through the SSO popup. On macOS 14.4 and newer the popup may stay a child window; on older macOS it opens in the main view. Both end signed in. canvas_sso_popup is recorded. A second popup while one is open is blocked.
5. Submit and finish: submit the quiz. About 2 s after the confirmation page, the app finishes the exam, the computer unlocks and Canvas is signed out (open the quiz link again after the next sign-in to FairPlay: Canvas asks for sign-in). Navigating away from the confirmation page within the 2 s must not finish the exam.
6. File upload question: open a quiz with a file upload question and click the upload button. No file panel opens and canvas_upload_unsupported is recorded.
7. Ordinary website exam: run a normal (non-Canvas) website exam. Allowed sites, finish URL and unlock behave as before, and no access code request is made.
8. Resume: quit the app mid-exam and reopen it, then resume. The page reloads, the code is filled again if the quiz asks for it, and the help alert only shows after a real failure (a 429 is retried up to 3 times, waiting the server's Retry-After, 1 to 20 s).
9. Device swap: after a swap to a second Mac, resume there. The second Mac fills the code; the first one is refused. Check canvas_code_issued / canvas_code_refused in the exam view: the server allows 6 code requests per attempt.

Restricted Canvas browser (needs a server that sends canvas_scope; use a test course with at least two courses, one other quiz and a course with pages, modules and files):

10. Sign in and dashboard: start a Canvas exam while signed out of Canvas. Sign in. When Canvas lands on the dashboard (or the course page), the app opens the exam quiz page once by itself. Go back to the dashboard by hand: it is not opened again.
11. Another course: before the quiz starts, open the dashboard, click another course. The page does not open, the strip shows "This page is not available during the exam." for a few seconds and blocked_navigation (canvas page /courses/<id>) is recorded. The quiz's own course page, the course quiz list and the exam quiz page do open.
12. Inbox and other pages: click Inbox, Profile, Calendar, Groups, Account in Canvas global navigation. All blocked with the message and an event, before the quiz and during it.
13. Quiz opens and code filled: open the exam quiz. The access code is typed only on that quiz page. Another quiz of the same course (with its own code) is blocked and gets no code.
14. Quiz phase: once the quiz page (classic: Take the quiz; new quizzes and assignments: the assignment page) has loaded, the dashboard, the course page and the course quiz list are blocked too. The quiz, its results page, sign-in hosts and Canvas /login pages keep working: let the Canvas session expire (or sign out in another browser) mid-quiz and check that signing in again works.
15. Open book off: during the quiz, Pages, Modules and Files links of the course are blocked.
16. Open book on: the teacher turns on open book and a new attempt starts. Course pages, modules and files open during the quiz; a file download link (/files/<id>/download) stays blocked; Inbox and other courses stay blocked.
17. Go to my quiz: from any allowed page, press "Go to my quiz" in the strip. The exam quiz page opens. Press it while on the quiz or while a page is still loading: nothing happens.
18. Back: with a previous allowed page in the history, "Back" goes there. During the quiz Back only returns to pages of the exam's Canvas host that are not sign-in pages. On the first page (history holds only the FairPlay page) or when the previous page is not allowed, Back is greyed out. Back never reaches a blocked page.
19. Popups and typed addresses: window.open or a link with target=_blank to /inbox is blocked with the message. Path tricks in a link (/courses/<id>/quizzes/<id>/../../../inbox, %2f, //) are blocked.
20. No scope: an exam created before canvas_scope existed (or whose link is not a /courses/.../quizzes|assignments/... link) behaves as in steps 1 to 9: any quiz or assignment of the exam host, no Go to my quiz or Back buttons.
21. Finish: submit the quiz as in step 5. The exam finishes, the computer unlocks and Canvas data is cleared.
22. In-page route changes: in the new quizzes or assignment page, use any in-page link that changes the address without a page load (for example a Canvas global navigation item in an open-book exam, or a link to /inbox). If the address becomes a blocked page, the app returns to the previous allowed page (or the exam quiz) within about a second, shows the message, and records one blocked_navigation (canvas page /... (in page)) per page. Clicking the same link repeatedly never makes the page flicker more than once per second.
23. First login at DKU Canvas: with a student account that has never signed in (or after resetting the terms-of-use acceptance), start a Canvas exam and complete the first-login steps, for example accepting the terms of use. /users, /profile and /accounts are blocked, so check that the first login still finishes and the exam link opens afterwards. If a step needs one of those pages, it must be done before the exam.
24. Broad allowed sites: a teacher-added wildcard such as *.instructure.com lets students follow links to any site under it (also other Canvas hosts and their /profile or /users pages). Check the allowed sites list of a real exam and keep it as narrow as possible.
25. Downloads: with open book on, a link with ?download=1 or ?download_frd=1 on a file is blocked, and a page that answers with an attachment is cancelled with the message.
26. Redirect loop: a link that keeps redirecting to a blocked page adds one blocked_navigation event per page, not one per redirect.
27. Popups: a link that opens a new window to a Canvas page of the exam host loads in the main view, not in a child window. A sign-in popup to another allowed host still works.
28. New Quizzes access code: New Quizzes run in a separate quiz-lti frame and the app does not fill that frame. For a New Quizzes exam the student types the code by hand (set the exam to manual and tell the students the code); managed codes are not supported there. Check that a New Quizzes exam with a code asks for it and that typing it works.
29. Sign-in pages during the quiz: Canvas-host /login and /login/** (same host only, exact path segments) stay open in the quiz phase so an expired session can sign in again. This is an addition to the written contract. Check that /login works during the quiz and that /loginx, /Login and /login/../inbox are blocked.
30. Finish pattern: a Canvas exam only finishes from finish_url_regex; finish_url_contains is ignored. With a finish pattern the app cannot use (too long or unsafe), the strip shows "The finish page could not be set up. Ask your teacher." and the exam view lists one blocked_navigation event (finish pattern rejected).
31. Web data: after finishing, sign-in cookies of other sites are cleared, but a site that shares its registrable domain with the FairPlay server (for example dku.edu) is kept, so Canvas can stay signed in on a Mac when both are under the same domain. Check which behaviour your deployment has and sign out of Canvas by hand if it matters.
32. Downloads: a link in Canvas that starts a download in the main view (a file attachment link) is cancelled with the message and a blocked_navigation event.
33. Stuck recovery: a page that keeps pushing a blocked address in the quiz brings the view back to the exam quiz up to 5 times at one per second, then once more to the exam link, then stops; the message stays.
